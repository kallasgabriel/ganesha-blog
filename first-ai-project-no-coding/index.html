What to Build First with AI: 3 Beginner Projects

A good first AI project is small, finishable in an afternoon and easy to check. Three projects to build without coding, plus a step-by-step and prompts.

A good first AI project is one you can finish in an afternoon, explain in one sentence, and check with your own eyes. For most beginners that means one of three things: a single web page, a small task app that saves your data, or an automation that turns a table into a report. Pick one, build it end to end, and you learn the loop that every later project uses: ask, build, test, correct.

The most common beginner mistake isn't picking the wrong tool. It's picking a project that's too big to ever feel finished — "an app like Airbnb", "a personal AI assistant". You can't tell whether it works, so you can't tell whether you're learning.

What makes a good first project

Run your idea through these four checks before you open an AI tool. If it fails one, shrink it.

  • One job. You can describe the whole thing in a single sentence without "and also".
  • Visible result. There's something to look at: a page, a screen, a file. Not a vague "it handles my workflow".
  • A pass/fail test. You know, before you start, what "it works" looks like. Example: "I add a task, refresh the page, the task is still there."
  • Finishable today. If it needs accounts, payments, logins and a database to be useful, it's your fourth project, not your first.

Notice that none of these are about AI. They're about scope. AI will happily build whatever you describe, which is exactly why describing something small is the skill.

Three first projects that actually work

1. A one-page site. A personal page, a page for a small service, a landing page for an idea you want to test. You end up with something you can look at in a browser and show someone. The test: it shows the right text and sections, it doesn't break when the window gets narrow, and the links go where they should.

2. A task app that remembers. Add a task, mark it done, delete it — and the data survives a refresh because it's saved locally in the browser. This is the first project where you deal with state, which is where real software starts. The test: add three tasks, close the tab, reopen it, and all three are still there. Add a backup and recovery step and you've learned something most beginners skip.

3. An automation that turns a table into a report. Give it a small spreadsheet of data and get back a summary — totals, trends, a short written recap. This is the most useful one at work, because it replaces something you currently do by hand. The test: compare the report to the source data and confirm the numbers match. Then feed it a broken row on purpose and see what happens.

A good order is site → app → automation, because each one adds exactly one new idea: layout, then stored data, then data you didn't write yourself.

Step by step: your one-page site this afternoon

Here's the whole loop, with real actions. Budget about two hours.

  1. Write the request before you open the tool. One paragraph, in plain language. What it is, who it's for, what sections it has, what it should look like.
  2. Paste the request into your AI tool (Codex, Claude or similar) and ask for a single HTML file so there's nothing to install.
  3. Open the result in your browser. Double-click the file. Don't read the code — look at the page.
  4. Compare the page to your request, line by line. Is every section there? Is the text yours or did the AI invent some? Is anything missing?
  5. Ask for one correction at a time. "The contact section is missing. Add it below the services section, with an email link." One change per request makes it obvious whether the fix worked.
  6. Test the awkward cases. Make the window narrow. Click every link. Try it on a phone screen size.
  7. Stop when it passes your test from step 1. Not when it's perfect.

A request you can copy and adapt:

Build a single-page website for a freelance photographer named Sara, as one self-contained HTML file with the CSS included, no external libraries. Sections, in this order: a header with her name and the tagline "Portraits and small events"; an about paragraph of three sentences; a services list with three items and prices left as placeholders; a gallery area with six image placeholders; a contact section with an email link. Style: light background, one accent colour, generous spacing, readable on a phone. Use placeholder text only where I haven't given you the content. Don't invent testimonials, awards or client names.

That last line matters more than it looks. AI tools fill gaps with plausible-sounding inventions. Telling them where to use placeholders instead is one of the fastest habits to pick up.

How to tell it actually works

Beginners tend to judge a result by whether it looks finished. Use these checks instead:

  • Does it match what you asked for? Open your original request next to the result and go line by line. Anything extra is also a mismatch.
  • Does it survive the boring case? Refresh the page. Reload the app. Run the automation twice with the same file.
  • Does it survive the ugly case? An empty task. A row with a missing value. A very long piece of text.
  • Can you explain what it does? If you can't describe how the thing works in plain language, you don't own it yet — ask the AI to explain its own result in simple terms.

When something breaks, describe the symptom, not the suspected cause: "I click Add and nothing appears in the list" works better than "I think the save function is broken". You're the one who can see the screen; that's your real contribution.

What to build after your first one

Once the loop feels natural, the upgrade path is small and boring on purpose: add one feature to the project you already have, rather than starting a new one. Add a second page to the site. Add due dates to the task app. Make the automation run on a schedule, with a check that tells you if it failed.

Frequently asked questions

What is the best first project to build with AI if I've never coded?

A single web page. It has a visible result, no setup, and you can judge it by looking at it. Once that feels easy, move to a small task app that saves data, then to an automation.

How long should my first AI project take?

An afternoon. If your idea can't reach a working version in a few hours, it's too big for a first project — cut it down to the one feature that makes it useful.

Do I need to install anything to start?

Not for a one-page site: ask for a single self-contained HTML file and open it in your browser. You do need a computer and access to an AI tool such as Codex or Claude, and some tools have their own costs.

What do I do when the AI's result doesn't work?

Describe the symptom in plain language — what you did, what you expected, what happened — and ask for one fix at a time. Then re-test the same way you did before, so you can tell whether the fix worked.

Can I build my first project on my phone?

It's not recommended. You'll be moving between the instructions, the AI tool and the result you're testing, which is much easier on a computer.
